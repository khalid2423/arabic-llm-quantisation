Quantising Qwen2.5 for Arabic on a Tesla T4

Custom GPTQ 8-bit reduced Qwen2.5-1.5B-Instruct’s model-load GPU memory by 42% and matched FP16’s 12 correct answers on a 30-question ArabicMMLU sample. Custom 4-bit reduced that memory by 63% and answered 3 questions correctly. FP16 delivered the highest output throughput in this test.

Experiment

I used one NVIDIA Tesla T4 in Google Colab and served each checkpoint with vLLM 0.34.0 in eager mode, with a 2,048-token context limit. The baseline ran in FP16. I used GPTQModel 7.12.2 to create 8-bit and 4-bit weight-quantised checkpoints from the same Qwen2.5-1.5B-Instruct source model. Both used GPTQ format, group size 128, and the same 64 calibration examples from the ArabicMMLU All/dev split at revision 9ea4eb3. Calibration examples included the question, available context, options and answer key.

For serving performance, I sent one warm-up request followed by five sequential Arabic prompts with temperature zero and a 64-token output cap. Response time is the median end-to-end latency. Output throughput is the sum of generated tokens divided by the sum of request durations. Total GPU use is an nvidia-smi snapshot after the five requests, while model-load GPU memory comes from the vLLM startup log.

For quality, I drew 100 candidate rows from All/test with Python’s random seed 42 and evaluated the first 30 requests that fit. Each configuration skipped two overlength prompts. The model was asked for a single Latin option letter, with temperature zero and an eight-token output cap. Replies without a valid single option letter counted as incorrect.

GPTQModel reported saved model sizes of 1,726.13 MB for 8-bit and 1,096.50 MB for 4-bit, down 41.38% and 62.76% from the original 2,944.44 MB. The local quantisation runs took 5 min 26 s and 5 min 36 s, respectively.

What the results show

Quantisation reduced the memory attributed to loading the model, while the running-server snapshots stayed close to 13.4 thousand MiB. These snapshots include vLLM allocations such as its KV cache. Under the tested T4 configuration, output throughput fell by 24.2% for custom 8-bit and 19.4% for custom 4-bit relative to FP16.

Custom 4-bit returned 16 replies outside the requested format. That makes the 10% exact-match score a measure of answer selection and format adherence together. The publisher’s 4-bit GPTQ checkpoint scored 13/30 in the same pilot, and its 8-bit checkpoint scored 12/30. The gap between the two 4-bit checkpoints warrants a closer look at quantisation settings, calibration and the raw responses before assigning a cause.

The results describe one T4 session, five timed requests per checkpoint and one small evaluation sample. They support a claim about model-load memory in this setup. Broader claims about Arabic quality or latency would need more questions, repeated measurements and additional serving configurations.
